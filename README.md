# あじぴたの内側

個人開発の食レビューサービス **あじぴた** の設計と運用の記録。

サービス本体のリポジトリは非公開のため、ここに**何をどう作り、なぜそう判断したか**を公開しています。
アーキテクチャだけでなく、コスト・CI・運用・開発プロセスまで含みます。

> 読み物として書いています。あじぴたを題材に、**個人開発で「判断を残しながら作る」とどうなるか**の実例として読んでください。

---

## あじぴたとは

> **味覚が近い人のリアルな評価を頼りに、外れない一皿に出会える**食の口コミ・マッチングサービス。

「食べログや Google マップの評価は高いのに、自分には合わなかった」——
その経験を解決するために、**店ではなく料理単位**で評価を収集し、味覚の近いユーザーの声を軸に推薦します。

| 項目 | 内容 |
| --- | --- |
| 形態 | Web アプリ（スマートフォン優先） |
| 開発 | 個人開発（1 人） |
| 状態 | **リリース済み**。全機能が稼働中で、改善・修正を継続 |
| 開発開始 | 2026 年 4 月（開発・運用とも継続中） |

現在は**改善と不具合修正を継続し、ある程度まとまった段階でリリースする**サイクルで運用しています。
有料プランの導入など、規模の大きな機能追加は次のフェーズで予定しています。

---

## 規模

「個人開発」という言葉から想像される規模と実態がずれるので、先に数字を置いておきます。

| 指標 | 値 |
| --- | --- |
| コミット数 | **4,100+**（アプリ本体 3,400+ / 運営コンソール 400+ / LP 230+ / 拡張 56） |
| 設計判断の記録（ADR） | 36 本 |
| DB マイグレーション | 176 本 |
| DB ロジックのテスト（pgTAP） | 79 ファイル |
| API エンドポイント | 49 本（アプリ本体 26 / 運営コンソール 23） |
| リポジトリ | 4 |

> 数値は開発ブランチ基準（「作った量」を示す指標として）。本番ブランチはリリース単位で追従します。

## 技術スタック

| 領域 | 使用技術 |
| --- | --- |
| フロントエンド | Next.js 16 / React 19 / TypeScript / Tailwind CSS 4 |
| バックエンド・DB | Supabase（PostgreSQL / Auth / Storage / RLS） |
| 店舗データ | HotPepper グルメサーチ API → Google Places API (New) へ段階移行中 |
| 地図 | Google Maps JavaScript API |
| ホスティング | Vercel（アプリ本体）/ Netlify（運営コンソール・LP）/ Supabase（DB・Auth・Storage） |
| バッチ | pg_cron + Supabase Edge Functions |
| 監視 | Sentry（エラー + Web Vitals）/ Vercel・Netlify・Supabase のログ |
| 分析 | GTM + GA4（同意管理付き） |

## このドキュメントの方針

- **判断の理由を書く。** 「何を使ったか」より「なぜそれを選び、何を捨てたか」
- **失敗と手戻りも書く。** 前提が崩れて決定をやり直した経緯も残す
- **数字を出す。** 実測値・試算・実際のコストで語る

一方で、以下は意図的に伏せています。

- サービスの差別化に直結するアルゴリズムの詳細
- セキュリティ上、公開が適切でない実装（管理画面の認証機構など）
- 内部の Issue 番号・環境変数名・具体的なテーブル定義
